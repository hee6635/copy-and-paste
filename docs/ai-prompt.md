# AI 정리 구조 · 프롬프트

> 코드가 바뀌면 이 문서도 같이 고친다. 원문: `app/src/main/java/com/hee6635/linkmemo/GeminiPrompt.kt` (정리) · `GeminiMore.kt` (긴 영상 목차 · 질문)

## 1. 흐름: 저장 → AI 정리 → 화면

1. **저장 (AI 비용 없음)** — 제목 · 설명(캡션) · 작성자 · 댓글 20개(작성자 답글 포함) · 영상("영상까지"일 때) · 인스타 사진 게시물이면 사진 전부 + 폰이 읽은 사진 속 글자 · 웹이면 본문
2. **보내기 전 거르기** — 쓸모없는 댓글(작성자 답글 없고 @태그 · 이모지 · 공백 · ㅋㅎ 빼면 6자 미만)은 빼고 보냄. 번호는 원래 번호 그대로(★ 가 맞게). (`junkComment`)
3. **AI 정리 (Gemini, `AiJob.kt`)**
   - 1단계 빠르게: 글만 보내 몇 초 만에 먼저 보여 줌 (`light`)
   - 2단계 자세히: 영상 + 글. 유튜브는 링크 그대로, 인스타는 영상을 잠깐 받아 올리고 지움, 사진 게시물은 사진 최대 10장
   - 실패하면: 받아쓰기 빼고 다시 → 글만으로 다시(`noVideo`, 화면에 경고 카드) · 답이 끊기면 살려서 보여 줌(`cut`, 경고 카드)
   - 모델: 최신 flash → 안정판 → lite 순서로 바꿔 가며
4. **답 받기** — 정해진 칸(JSON 스키마)으로만. 순서: 종류 → 지역 → 장소 → 레시피 → … → 팁 → ★ → 갈래 → 폴더 → 태그 → … → 받아쓰기(맨 뒤, 끊겨도 앞 칸은 남게). 갈래 · 폴더는 내용을 다 쓴 뒤에 고르게 (앞에 두었더니 라면 레시피를 "디자인"으로 고름)
5. **화면용으로 바꾸기 (`Gemini.normalize`)** — 예전 메모와 같은 모양으로 저장해서 화면 · 복사 · 슬라이드 · 캡처 · 질문을 그대로 씀
   - tips(label · text · from · t · who) → summary(글) + sumFrom(출처 칩: 영상 / 작성자 댓글 / 댓글 / 본문 / 사진) + sumLabel(이름표) + sumMeta(출처 · 시각)
   - 레시피 순서 {text, t} → 글 + stepT(시각)
   - keyshots sec tips → summary
   - 레시피면 갈래는 무조건 요리 · 영상 길이를 넘는 시각은 -1
   - 예전 메모(summary · facts 가 이미 있음)는 그대로 예전 모양으로 보임
6. **태그 (`applyTags`)** — 다시 정리할 때 지난번 AI 태그(aiTags)는 새 것(최대 4개)으로 바꾸고, 직접 넣은 태그는 둠

## 2. 칸과 화면

| 칸 | 화면 | 요약 |
|---|---|---|
| kind … category → folder | 종류 · 갈래 · 폴더 추천 | 내용을 다 쓴 뒤 갈래를 정하고 그 주제에 맞는 폴더만 고름 |
| area · listName | 📍 · 경로 보기 검색어 / 목록 제목 | 도시 이름 하나 / 장소가 아니면 항목 종류 |
| places (+ day · map) | 간 곳 / 스킬 10 · DAY 칩 · DAY별 경로 · map false 는 흐리게(경로 · 📍 제외) | 나온 순서대로 전부, info 70~90자. 필수 · 필요 없음 판단은 안 함 (저장한 사람이 필요해서 저장한 것). 작성자가 강조했으면 info 에 그대로 |
| recipe (servings · ingredients · steps{text, t}) | 재료(인분 조절) · 순서(영상 시각) | 순서 문장엔 절대 용량을 쓰지 않음, 생활 계량은 그대로 |
| checklist · events | 체크리스트 · 일정 | 해당할 때만 |
| tips (label · text · from · t · who) | 꼭 알아둘 팁: [출처 칩] **이름표** 내용 | 장소 · 레시피가 있으면 0~5개(빈 목록 허용), 없으면 핵심 요약 3~6개 |
| star | 댓글 ★ (위로) | 실질 정보 있는 댓글 번호 (보낸 번호 그대로) |
| links | 바로 쓰기 카드: 명령어 [복사] · 링크 [열기] | 원문에 나온 것만 |
| title | 보이는 제목 (원본 제목은 그대로 남음) | 댓글 유도 문구일 때만 새로 |
| sections | 추가 묶음 카드 (목록 · 순서 · 표 · 이름: 값 · 글) | 위 칸에 안 맞는 묶음만, 0~3개 |
| tags | 태그 | 2~4개, 갈래와 겹치지 않게 |
| keyshots | 자동 캡처 | 정보가 보이는 장면 3~5개 (영상 있을 때) |
| desc_ko · transcript | 번역 · 받아쓰기 | 영상 있을 때만 받아쓰기 |

없앤 칸: summary · facts · course · sumFrom (예전 메모에만 남아 있음)

## 3. 정리 규칙 글 (앱 업데이트 없이 바꾸기)

- 원문: `app/src/main/assets/prompt/organize.txt` — 갈래 목록 자리는 `{{CATEGORIES}}` (앱이 채움)
- **바꾸는 법**: 이 파일을 고쳐 기본 브랜치에 올리면 끝. 앱을 열 때마다 (설정 › AI 정리 규칙 › 지금 받기로 바로) `raw.githubusercontent.com/hee6635/copy-and-paste/HEAD/…/organize.txt` 를 받아 씀. 이 경로는 APK 빌드가 안 돎(빌드 비용 0)
- **안전장치**: 받은 글에 places · tips · links · star · category · {{CATEGORIES}} · folder · transcript 가 다 있고 800자 넘어야 씀. 아니면 앱에 든 글
- 어느 글을 썼는지는 메모 원본 탭 AI 기록의 "정리 규칙" 줄 (저장소 날짜 / 앱 기본)
- 칸 모양(스키마)은 앱 안(GeminiPrompt.kt). 새 칸이 필요하면 앱 업데이트. 대신 **sections(추가 묶음)** 으로 list · steps · table · kv · text 모양은 앱 고치지 않고 늘릴 수 있음

## 4. 프롬프트 뒤에 붙는 재료

```
오늘: 2026-11-20
내 폴더: 여행 › 나트랑 / 디자인 / …
[출처] instagram · 아이디
[제목] …
[설명] … (최대 6천 자)
[본문] … (웹, 최대 8천 자)
[내 메모] …
[사진] N장이 같이 와요 … + [사진 속 글자 (폰이 읽음, 틀릴 수 있음)]
[댓글] 1. @아이디: 내용 (댓글마다 400자, 쓸모없는 댓글은 빠져서 번호가 건너뜀)
   ↳ [작성자 답글] @아이디: 내용
```
+ 파일: 영상(또는 유튜브 링크, 사진 게시물이면 사진)

## 5. 다른 프롬프트 (`GeminiMore.kt`)

- **긴 영상(10분 넘음)**: 5분씩 나눠 목차(시각 · 제목 15자 · 핵심 한 줄). 자막 있으면 글만, 없으면 유튜브 링크의 그 구간을 5초에 한 장면. 유튜버 목차가 있으면 그 경계를 따름. 만든 목차를 [설명]에 붙여 위 정리 프롬프트로 한 번 더.
- **질문하기**: "아래 [내 메모]에 있는 내용으로만 답하기. 없으면 '저장한 것 중에는 없어요'". answer 2~5줄 + refs(근거 메모 id 최대 5개). 홈에서 물으면 관련 메모 최대 120개를 짧게, 상세에서 물으면 그 메모 하나를 자세히(설명 · 본문 · 받아쓰기 · 댓글).
