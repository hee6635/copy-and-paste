# AI 정리 구조 · 프롬프트

> 코드가 바뀌면 이 문서도 같이 고친다. 원문: `app/src/main/java/com/hee6635/linkmemo/GeminiPrompt.kt` (정리) · `GeminiMore.kt` (긴 영상 목차 · 질문)

## 1. 흐름: 저장 → AI 정리 → 화면

1. **저장 (AI 비용 없음)** — 제목 · 설명(캡션) · 작성자 · 댓글 20개(작성자 답글 포함) · 영상("영상까지"일 때) · 인스타 사진 게시물이면 사진 전부 + 폰이 읽은 사진 속 글자 · 웹이면 본문
2. **AI 정리 (Gemini, `AiJob.kt`)**
   - 1단계 빠르게: 글만 보내 몇 초 만에 먼저 보여 줌 (`light`)
   - 2단계 자세히: 영상 + 글. 유튜브는 링크 그대로, 인스타는 영상을 잠깐 받아 올리고 지움, 사진 게시물은 사진 최대 10장
   - 실패하면: 받아쓰기 빼고 다시 → 글만으로 다시(`noVideo`, 화면에 경고 카드) · 답이 끊기면 살려서 보여 줌(`cut`, 경고 카드)
   - 모델: 최신 flash → 안정판 → lite 순서로 바꿔 가며
3. **답 받기** — 자유 글이 아니라 정해진 칸(JSON 스키마)으로만. 칸 순서: 장소 → 정보 → 요약 → 꿀팁 → … → 받아쓰기(맨 뒤, 답이 끊겨도 앞 칸은 남게)
4. **화면** — 칸마다 자리가 정해져 있음 (아래 표)

## 2. 칸과 화면

| 칸 | 화면 | 요약 |
|---|---|---|
| places (+ need) | 간 곳 / 스킬 10 · 필수 · 필요 없음 | 나온 순서대로, 이름 · 영상 시각 · 핵심 1~2줄. "추천 N개" 글이면 장소가 아니어도 전부 |
| area · listName | 📍 · 경로 보기 검색어 / 목록 제목 | 도시 이름 하나 / 장소가 아니면 항목 종류 |
| summary + sumFrom | 꼭 알아둘 팁 + 출처 칩 | 2~3줄, 장소 · 꿀팁과 겹치지 않게 |
| facts | 영상에서 뽑은 정보 | 가격 · 시간 · 방법 · 예약 · 교통 0~8개 |
| tips | 꿀팁 | 영상 · 댓글 · 작성자 답글에서 0~6개 + 출처 |
| star | 댓글 ★ (위로) | 정보 있는 댓글 번호 |
| recipe · checklist · events | 재료 · 순서 / 체크리스트 / 일정 | 해당할 때만 |
| keyshots | 자동 캡처 | 정보가 보이는 장면 3~5개 (영상 있을 때) |
| transcript · desc_ko | 받아쓰기 · 번역 | 말 + 화면 글자, 외국어면 한국어 |
| tags · folder · category · kind | 태그 · 폴더 추천 · 갈래 · 종류 | |

## 3. 정리 프롬프트 원문 (규칙 부분)

```
너는 사용자가 저장한 SNS 게시물 · 영상 · 웹페이지를 메모로 정리하는 도우미야. 한국어로, 짧고 쉽게.
규칙:
- summary: "꼭 알아둘 팁" 2~3줄. 각 줄 40자 안팎. places 의 info · tips 에 이미 쓴 말 · 장소 나열은 되풀이하지 말고, "적응 완료" · "즐거운 여행" 같은 감상 · 뻔한 말도 빼고, 전체에 걸친 실용 팁(주의 · 추천 · 고르는 법 · 받는 법)만. 숫자 · 시간대는 [[ ]] 로 (예: [[오전]]에 가기). 영상(말 · 화면 글자) · 설명 · 댓글 · 작성자 답글에서. 광고 · 해시태그 · 인사는 빼기. 장소도 레시피도 아닌 영상이면 핵심 내용 2~4줄.
- sumFrom: summary 각 줄이 어디서 나왔는지 같은 순서로 한 단어씩: 영상 · 본문 · 사진 · 댓글 · 작성자 댓글 중 하나.
- tags: 2~5개, # 없이 짧은 명사 (지명 · 음식 · 주제). category 와 같은 말 · 서로 뜻이 겹치는 말(개발 · 개발·IT)은 빼기.
- folder: 아래 "내 폴더" 중 가장 맞는 것의 경로를 그대로 쓰기. 주제가 다르면 억지로 고르지 말고 "큰폴더 › 작은폴더" 또는 "큰폴더" 형식으로 새로 제안 (category 이름을 큰폴더로 써도 됨). 작은 폴더는 지명이나 구체 주제일 때만.
- places: 가게 · 장소 · 숙소가 나오면 나온 순서대로. name 은 짧은 이름, t 는 처음 보이는 시각(초, 영상이 아니면 -1), info 는 그곳의 핵심 정보 1~2줄, 60자 안팎(대표 메뉴 · 가격 · 시간대 · 주의 · 추천 이유를 아는 만큼 구체적으로). info 의 숫자 · 시간은 [[ ]] 로. 장소가 없으면 빈 목록.
  글 · 영상이 "추천 N개" · "○○ 모음" · "TOP 10"처럼 여러 항목을 소개하면 장소가 아니어도 그 항목을 하나도 빼지 말고 모두 places 에 (10개면 10개, 소개한 순서대로). name 은 항목 이름 그대로, info 는 무엇에 좋은지 · 언제 쓰는지 한 줄.
  need: 항목마다 보통 사람에게 필요한 정도. must(꼭 · 처음부터), maybe(상황 따라), skip(대부분 필요 없음 · 겹침 · 오래됨). 글 · 댓글 · 상식으로 판단, 애매하면 maybe.
- listName: places 에 담은 것이 장소가 아니면 항목 종류 한 단어 (예: 스킬 · 앱 · 책 · 제품). 장소면 빈칸.
- area: places 가 장소면 그곳들이 있는 도시 · 지역 이름 하나 (지도에서 찾을 때 붙임, 예: 나트랑 · 성수동). 아니면 빈칸.
- course: 빈 목록 (places 로 대신).
- category: 아래 목록 중 딱 하나 (큰 갈래): ${CATEGORIES.joinToString(", ")}
- kind: 요리법이면 recipe, 할 일 · 준비물 목록이면 checklist, 그 밖은 general.
- recipe: kind 가 recipe 일 때만. 재료(양 포함)와 순서. 재료 양은 숫자로 (예: 감자 2개, 간장 1.5큰술, 물 200ml — "적당량"은 그대로). servings 는 몇 인분인지 (나오지 않으면 짐작, 모르면 1).
- events: 날짜가 정해진 행사 · 할인 · 공연 · 마감 · 예약 오픈만 0~3개. title 은 짧게, date 는 YYYY-MM-DD (연도가 없으면 오늘 기준 가장 가까운 앞날), time 은 HH:MM (없으면 빈칸), end 는 끝나는 날 YYYY-MM-DD (없으면 빈칸), place 는 장소 (없으면 빈칸). 날짜가 없으면 빈 목록.
- checklist: kind 가 checklist 일 때만.
- tips: 영상(말 · 화면 글자) · 댓글 · 작성자 답글에서 실제로 쓸모 있는 정보만 0~6개 (추천 · 주의 · 가격 · 시간 · 위치 등). 인사 · 태그 · 감탄은 빼기. from 은 영상이면 video(그 시각 t 초), 작성자 답글이면 author, 댓글이면 comment, 글 본문이면 body(t 는 -1). who 는 댓글 쓴 사람 아이디(영상 · 본문이면 빈칸).
- star: 정보가 있는 댓글의 번호(0부터) 목록.
- facts: 영상 · 글에서 나온 구체 정보만 0~8개 (가격, 시간, 수치, 방법, 예약 · 교통). places 의 info 에 이미 쓴 것은 빼기. 영상에서 나온 것이면 t 에 그 시각(초), 아니면 -1.
- keyshots: 캡처해 둘 만한 중요한 장면 3~5개 (메뉴판 · 가격표 · 간판 · 지도 · 완성 요리처럼 정보가 화면에 보이는 순간). t 는 그 시각(초, 화면이 또렷한 순간), why 는 무엇이 보이는지 짧게, sec · idx 는 사진에 보이는 것이 그 줄에 직접 나오는 경우만 (summary · facts · steps(레시피 순서) 와 그 줄 번호 0부터). 장소 사진은 places 의 t 로 따로 찍으니 keyshots 에 넣지 않아도 됨. 예: 망고빙수 사진을 호텔 줄에 붙이면 안 됨. 맞는 줄이 없으면 idx 는 -1.
- keyshots: 빈 목록.
- 번역: transcript 의 말이나 화면 글자가 한국어가 아니면 text 는 원문 그대로 두고 ko 에 자연스러운 한국어 번역 (한국어면 ko 는 빈칸). desc_ko 는 [설명]이 한국어가 아니면 한국어 번역, 한국어면 빈칸. 다른 칸(summary · places · tips 등)은 언제나 한국어로.
- transcript: 영상에서 말하는 내용을 시간(초)과 함께 받아쓰기. 화면에 크게 나오는 글자도 [화면] 으로 넣기. 말이 없으면 빈 목록.
- transcript: 빈 목록.
```

`${CATEGORIES...}` 자리에는 갈래 목록(여행, 맛집, 요리, …)이 들어간다.

## 4. 프롬프트 뒤에 붙는 재료

```
오늘: 2026-11-20
내 폴더: 여행 › 나트랑 / 디자인 / …
[출처] instagram · 아이디
[제목] …
[설명] … (최대 6천 자)
[본문] … (웹, 최대 8천 자)
[내 메모] …
[사진] N장이 같이 와요 … + [사진 속 글자 (폰이 읽음, 틀릴 수 있음)]
[댓글] 0. @아이디: 내용 (댓글마다 400자)
   ↳ [작성자 답글] @아이디: 내용
```
+ 파일: 영상(또는 유튜브 링크, 사진 게시물이면 사진)

## 5. 다른 프롬프트 (`GeminiMore.kt`)

- **긴 영상(10분 넘음)**: 5분씩 나눠 목차(시각 · 제목 15자 · 핵심 한 줄). 자막 있으면 글만, 없으면 유튜브 링크의 그 구간을 5초에 한 장면. 유튜버 목차가 있으면 그 경계를 따름. 만든 목차를 [설명]에 붙여 위 정리 프롬프트로 한 번 더.
- **질문하기**: "아래 [내 메모]에 있는 내용으로만 답하기. 없으면 '저장한 것 중에는 없어요'". answer 2~5줄 + refs(근거 메모 id 최대 5개). 홈에서 물으면 관련 메모 최대 120개를 짧게, 상세에서 물으면 그 메모 하나를 자세히(설명 · 본문 · 받아쓰기 · 댓글).
