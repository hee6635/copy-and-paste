# /ship — 올리기 전 점검

코드를 올리면 APK 빌드(.github/workflows/build-apk.yml)가 돌아 비용이 든다.
망가진 채로 올리지 않는 게 목적. **사용자가 "올려"라고 해야만 이 스킬을 쓴다.**

## 순서

1. **바뀐 것 보기**: `git status --short` · `git diff --stat`
   - 바뀐 게 `design/ docs/ *.md .claude/` 뿐이면 빌드가 안 돈다 → 점검 건너뛰고 3번으로.
2. **점검**: `node .claude/skills/ship/check.js <scratchpad 폴더>`
   - ✕ 화면 오류 → 고치고 다시 점검. 고칠 수 없으면 멈추고 사용자에게 말한다.
   - 스크린샷(`ship-home.png`)을 Read 로 열어 화면이 깨졌는지 본다.
   - 바뀐 화면이 홈이 아니면 그 화면도 Playwright 로 눌러 들어가서 확인한다.
   - `! 긴 파일` 은 **이번에 고친 파일**만 신경 쓴다. 이번에 500줄을 넘겼으면 나누자고 제안(지금 나눌지는 사용자가).
   - `.kt` 를 고쳤으면: 여기선 컴파일 확인을 못 한다. 괄호 · import · 이름을 눈으로 한 번 더 본다.
3. **확인 받기**: 아래 모양으로 짧게 보여주고 "올릴까요?" 묻는다. 대답 전에는 푸시하지 않는다.
   ```
   바뀐 것: (한 줄씩, 쉬운 말)
   점검: ✓ 화면 오류 없음 / ! 주의할 점
   APK 빌드: 돎 / 안 돎
   ```
4. **승인하면**: 커밋(한국어 · 짧게) → 지금 브랜치에 `git push -u origin <브랜치>`.
   - 빌드가 안 도는 변경만 있으면 커밋 메시지에 `[skip ci]` 를 붙여도 된다.
