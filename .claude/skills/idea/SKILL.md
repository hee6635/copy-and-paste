# /idea — 기획 다듬기

아이디어를 듣고, 모르는 것만 묻고, 판단해서 TODO 에 적는다. **코드는 고치지 않는다.**

## 순서

1. **먼저 본다**: `docs/TODO.md` (이미 있거나 비슷한 게 있는지), 관련 화면 · 파일을 짧게 훑는다.
   코드에서 알 수 있는 건 묻지 않는다.
2. **묻는다**: 정말 갈리는 것만, 한 번에 최대 3개. AskUserQuestion 으로 고를 수 있게.
   좋은 질문: 언제 쓰나 · 어느 화면에 · 안 되면 어떻게 · AI 횟수/비용이 드나.
   답이 충분해질 때까지 반복하되 보통 1~2번이면 끝낸다.
3. **판단**을 먼저 말한다 (결과 먼저, 짧게):
   - 👍 좋음 → 한 줄 이유
   - 👎 별로 → 이유 + 대안
   - 크기: 작음 / 중간 / 큼 · 손댈 파일 · AI 비용이 늘어나는지
4. **승인하면** `docs/TODO.md` 의 맞는 단계에 한 줄로 적는다. 기존 줄 모양을 따라:
   `- 기능 이름: 무엇을 · 어떻게 · 예외 (짧게, ` · ` 로 이어서)`
   화면이 바뀌는 기능이면 "시안 먼저 볼까요?" 묻고 원하면 /mockup.
5. TODO 만 바뀐 건 APK 빌드가 안 돈다. 커밋 · 푸시는 사용자가 "올려"라고 할 때.
